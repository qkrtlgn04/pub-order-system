# 주점 QR 주문 시스템 — 설치 가이드

손님이 테이블의 QR을 스캔 → 메뉴를 보고 주문 → 계좌이체 → 주방 화면에 순서대로 주문이 뜨고,
스태프가 입금을 확인하면 손님 화면에도 바로 반영되는 구조입니다.

- `index.html` — 손님용 주문 페이지 (QR로 연결)
- `kitchen.html` — 스태프용 주방 화면 (주문 현황 / 메뉴 관리 / 설정 / QR)
- `firebase-config.js` — 두 페이지가 함께 쓰는 연결 설정 (직접 값을 채워야 함)
- `firestore.rules` — 데이터베이스 보안 규칙 (Firebase 콘솔에 붙여넣기)

실시간 공유 데이터(주문 목록, 메뉴, 결제 상태)는 **Firebase**(구글의 무료 백엔드 서비스)를 사용합니다.
무료 티어로 충분하고, 카드 등록 없이 시작할 수 있습니다. 총 소요 시간 약 10~15분.

---

## 1. Firebase 프로젝트 만들기

1. https://console.firebase.google.com 접속 → 구글 계정 로그인
2. **"프로젝트 추가"** 클릭 → 이름 입력(예: `우리주점`) → 애널리틱스는 꺼도 무방 → 프로젝트 생성

## 2. Firestore(데이터베이스) 켜기

1. 왼쪽 메뉴 **빌드 → Firestore Database** → "데이터베이스 만들기"
2. 위치는 `asia-northeast3(서울)` 추천
3. 보안 규칙은 일단 "테스트 모드"로 시작해도 되고, 바로 아래 3단계 규칙을 넣어도 됩니다
4. 생성 후 **규칙(Rules)** 탭으로 이동 → 이 폴더의 `firestore.rules` 내용을 전부 복사해서 붙여넣고 **게시(Publish)**

## 3. 익명 로그인(Anonymous Auth) 켜기

손님이 별도 회원가입 없이 바로 주문할 수 있도록 "익명 로그인"을 켜야 합니다.

1. 왼쪽 메뉴 **빌드 → Authentication** → "시작하기"
2. **Sign-in method** 탭 → **익명(Anonymous)** 선택 → 사용 설정 → 저장

## 4. 웹 앱 등록 & 설정값 복사

1. 프로젝트 개요 옆 **⚙️(설정) → 프로젝트 설정**
2. 아래로 스크롤해서 **"내 앱"** → 웹 아이콘(`</>`) 클릭
3. 앱 닉네임 입력(예: `pub-app`) → "Firebase Hosting 설정"은 체크 안 해도 됨 → 앱 등록
4. 화면에 나오는 `firebaseConfig` 값을 복사
5. 이 폴더의 **`firebase-config.js`** 파일을 열어서, `apiKey`, `authDomain`, `projectId`, `storageBucket`,
   `messagingSenderId`, `appId` 값을 복사한 값으로 그대로 교체 후 저장

## 5. 배포(호스팅) — 손님이 접속할 수 있는 주소 만들기

파일을 그냥 더블클릭해서 열면 `file://` 주소라 일부 기능이 제대로 동작하지 않을 수 있어요.
아래 두 방법 중 편한 걸 고르세요.

### 방법 A — Netlify Drop (가장 쉬움, 코딩/설치 불필요)

1. https://app.netlify.com/drop 접속
2. 이 폴더(`pub-order-system`) 전체를 화면에 드래그 앤 드롭
3. 몇 초 후 `https://xxxxx.netlify.app` 같은 주소가 발급됩니다
4. 손님용 주소 = `발급된주소/index.html`, 주방용 주소 = `발급된주소/kitchen.html`

> 무료 계정으로 가입해두면 나중에 같은 주소로 다시 배포(업데이트)할 수 있어 더 편합니다.

### 방법 B — Firebase Hosting (Firebase CLI 사용, 조금 더 손이 감)

터미널(명령 프롬프트)에서:

```bash
npm install -g firebase-tools
firebase login
cd pub-order-system
firebase init hosting   # Firestore는 이미 만들었으니 Hosting만 선택, public directory는 "." (현재 폴더)
firebase deploy
```

배포가 끝나면 `https://프로젝트ID.web.app` 형태의 주소가 나옵니다.

## 6. 처음 실행 — 주방 화면 설정

1. 배포된 주소 + `/kitchen.html` 접속
2. 기본 PIN **`1234`** 입력해서 입장
3. **설정** 탭에서:
   - 상점 이름
   - 은행명 / 계좌번호 / 예금주 (손님 결제 화면에 그대로 노출됩니다)
   - PIN을 새로운 값으로 변경 (꼭 하세요!)
4. **메뉴 관리** 탭에서 예시 메뉴(생맥주, 소주 등)를 실제 메뉴로 수정/삭제/추가
5. **QR 코드** 탭에서 손님용 주소(`.../index.html`)가 맞는지 확인 후 인쇄해서 테이블에 부착
6. **주문 현황** 탭에서 실시간으로 들어오는 주문을 확인 → "입금 확인" → "준비 완료" 순으로 처리

행사 전 테스트 주문을 넣어봤다면, 설정 탭 맨 아래 **"전체 주문 내역 초기화"**로 정리하고 시작하세요.

## 동작 방식 요약

- 손님이 `index.html`에 접속하면 자동으로 "익명 로그인"되어 메뉴를 보고 장바구니에 담습니다.
- **주문하기** → 입금자명 입력 + 계좌 정보 확인 + **입금 완료 화면 캡처 첨부** → **주문 확정**을 누르면
  주문이 Firestore에 저장되고 순번이 매겨집니다. (캡처 이미지는 손님 브라우저에서 자동으로 축소·압축된 뒤 저장됩니다)
- 저장된 주문은 `kitchen.html`의 **주문 현황**에 실시간으로(수 초 이내) 순서대로 나타나며, 새 주문이 오면
  알림음과 함께 카드가 반짝입니다. 각 주문 카드에는 손님이 첨부한 입금 캡처 썸네일이 함께 뜨고, 탭하면 크게 볼 수 있어요.
- 스태프가 그 캡처(또는 실제 은행 앱)로 입금 내역을 확인한 뒤 **"입금 확인"**을 누르면, 손님 화면의 주문 상태도
  즉시 "입금 확인 완료 · 준비중"으로 바뀝니다. **"준비 완료"**를 누르면 손님에게 "픽업해주세요" 안내가 뜹니다.

## 알아두어야 할 점 (중요)

- **실제 계좌이체 자체는 이 앱이 처리하지 않습니다.** 손님이 본인 은행 앱으로 직접 이체하고,
  스태프가 계좌 입금 문자/앱을 보고 수동으로 "입금 확인" 버튼을 누르는 구조입니다.
  (개인/소규모 행사에서 PG사 없이 계좌이체를 받는 가장 현실적인 방법입니다.)
- 이 프로젝트의 Firestore 보안 규칙은 "익명 로그인한 사람이면 누구나 메뉴·주문을 쓸 수 있음" 수준의
  가벼운 규칙입니다. 하룻밤 행사용으로는 충분하지만, 주방 PIN을 아는 사람만 `kitchen.html`에 들어갈 수
  있게 해서 주문 상태 조작을 막고 있습니다. 행사가 끝나면 Firebase 프로젝트를 삭제하거나 규칙을 잠가두세요.
- 입금 확인 캡처 이미지는 무료(Spark) 요금제의 Firestore 문서 용량 제한(문서 1개당 256KiB) 안에 들어가도록
  자동으로 축소·압축해서 저장합니다. 화질이 아주 낮게 보일 수 있지만 "입금 완료" 문구/금액을 확인하는
  용도로는 충분해요. 손님이 너무 큰 사진을 올려서 이 한도를 넘으면 "이미지 용량이 너무 커요" 안내와 함께
  다시 시도하라고 안내됩니다.
- Firebase 무료 티어(Spark 플랜)로 충분한 규모입니다. 손님이 아주 많다면 Firebase 콘솔의 사용량을
  한 번씩 확인해보세요.
